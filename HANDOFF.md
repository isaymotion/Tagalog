## 3. Architecture and data formats
Static site, vanilla JS, no build step. `index.html` loads scripts in order: `data/app-meta.js`, `data/changelog.js`, `data/hospital.js`, `data/strings.js` → `js/data/*` (psych-withdrawal.js, then psych-answers.js, affixes.js, meta.js last) → `conjugate.js` → `audio-key.js` → `lang.js` → `core.js` → `views.js` → `psych-views.js` → `point-listen.js` → `handout.js` → `mse-sheet.js` → `sud.js` → `mood.js` → `withdrawal.js` → `deesc.js` → `discharge.js` → `discharge-practice.js` → `mse-practice.js` → `affixes.js` → `grammar-handout.js` → `app.js`. Hash routing (`#/path?query`) in `app.js` `routes`.

Navigation conventions (2.4.1 to 2.7.0, all in `app.js` unless noted):
- Phone tab bar: Home, Psychiatry, Practice, Cards, More. Dictionary is reachable from the header search, the desktop rail, More (first under Learn) and the Home footer line. `#/practice` (`V.practice` in app.js, registered with `routes.push` after `V.more` because it is defined after the routes array) lists every drill in Language and Clinical groups.
- Psychiatry hub (`psych-views.js` `V.psych`) has four tabs read from `?tab=`: `interview` (default; phrase sections + related lessons + the practice-phrasings notice), `cases`, `tools`, `print`. Tab pills are `.ptabs`, sticky under the top bar. Add a new psychiatry page to the right tab's tile list there and to `PSY_TOOLS` in app.js.
- `NAV` is the single list of top-level pages (key, hash, title, icon): it renders the desktop rail and the phone More screen (grouped Learn / You, with `BLURB` one-liners), plus `PSY_TOOLS` for the psychiatry tools group. A new top-level page goes in `NAV`, `TITLES`, `MORE_KEYS` (so the More tab highlights) and the `core.js` search `Page` list.
- `render()` calls `App.decorate(view, path, q, key)` after every view: it inserts a `.breadcrumb` on any deep page (two or more path segments) that did not draw its own, using `TITLES[key]` and the `PARENT` map for nested lists (`/psych/dcase` → Discharge practice, `/psych/mcase` → Admission MSE practice, `/psych/case` → Case simulations), and appends a pin button (`.pin`) to the `h1` of every page not in `NO_PIN`. Pins live in `state.pins` `[{hash,title,sec}]` (max 12); recents in `state.recent` `[{hash,title,sec}]` (last 8). `sec` is the section label from the breadcrumb.
- Home (`views.js` `V.home`): hero, What's New tile when unseen, stats, **Today** (cards due or start a deck; a quick-practice tile that rotates daily through verbs, panlapi, interpretation drill, psych flashcards, case simulation; next lesson; placement if no level), **Pinned**, **Continue** (recents not pinned), four psychiatry shortcuts, and a line pointing to Dictionary and More. There is no "Everything" grid any more.
- Text size: `#textSizeBtn` (Aa) in the top bar opens `#textSizePanel`; `App.applyTextSize()` sets `documentElement.style.fontSize` from `state.settings.textSize` (90 / 100 / 112.5 / 125); an inline head script applies it before first paint; Settings → Appearance has the same `App.textSizeSeg()`. CSS: `.stack > *` and `.row > label` have `min-width: 0` and `select.input` `max-width: 100%` so long selects fit at 125% on phones; test new pages at 125% on 390px.

## 8. Pitfalls learned
- **Dictionary words are append only.** Add new words at the END of `js/data/dict-themes.js` (`DICT_RAW2`). Never add, delete or reorder a line in the four old `dict-*.js` files or earlier in `dict-themes.js`: ids (`d<n>`) are positions and users' flashcard progress is saved under them. `tests/dict-ids.json` is a snapshot of id → word; data_check fails if any id changes. After adding words run `node tests/data_check.js <repo> --write-dict-ids` and commit the snapshot. A new entry with the same headword AND English as an old one is silently dropped (dedupe), so check the count.
- `tools/texts.json` and `tools/caps.json` are written by `collect-texts.js` and committed by the audio job; `git checkout` them before committing a release so the job's commit does not conflict.
- `runQuiz` shows `q.say` as a speaker button BEFORE the answer; for a gap question that would give the answer away. Use `q.sayAfter`.
- Build drill: Tagalog word order is flexible. Chunk free phrases into one tile (`ang gamot`, `sa gabi`) and list every natural order in `alt`, or a correct answer is marked wrong.
- Stage directions in case lines: write them at the start of the line or next to an ellipsis (`(tumango) ...Opo.`, `sabi nila... (tumigil) ...Ano po?`) so `App.spoken` drops them. A bracket in the middle of a sentence is spoken.
- Carlo, Arnel, Mika and Liza are first admissions; Ramon is the only readmission. Check which form a case belongs to before adding it.
- The project doc `claude/handoff.md` (claude.ai Project) is a copy of this file; it lagged at 2.9.1 until 2026-11-08. When a session ends, write this file back to the project doc too, or the next session restores the wrong baseline.
- When appending a generated button to a grid item, set grid-row/column on the node you insert (or use a class), not on a wrapper `div` you then discard (the 3.1.0 lesson-example bug).
- The session's safety check blocks `rm -rf` of a directory under the working tree root (it refused `rm -rf /home/claude/isaymotion`); leave stray clones alone and tell her.

- `check_design.py` requires a `tl:` block in `data/strings.js`, so it fails on Hablemos (`es`); the Hablemos dev-tools branch has a variant that accepts `es`. Decide with her whether the skill's rule should become "en + one other language".
- `check_design.py` takes the FIRST `x.y.z` in `data/changelog.js`; a version number in the header comment made it report "versions disagree". The comment now says "before version 3".
- The dev-tools branch already exists; never `git worktree add -B dev-tools … origin/main` (it would reset it). Fetch it explicitly (`git fetch origin refs/heads/dev-tools:refs/remotes/origin/dev-tools`) and branch from `origin/dev-tools`.
- `tests/data_check.js` loads scripts by scanning `index.html` for `src="js/…"` and `src="data/…"`; a new engine file that `core.js` depends on (like `lang.js`) must be in its filename filter or core.js throws at load.
- Network is allowlisted (package registries + GitHub only). Google Fonts, Hugging Face, Microsoft speech endpoints are blocked here; that's why audio is recorded by the GitHub Actions job. `gh` GraphQL is blocked: use `gh api` REST (e.g. `gh workflow run` fails; the dispatch POST works). Enabling Pages via API is blocked (already enabled).
- The audio job commits `audio/` to `main` within a minute of any push that touches `js/data/**`. Always `git fetch origin main && git rebase origin/main` before pushing a second time, or the push is rejected as non-fast-forward.
- Action logs can't be downloaded here; the audio job writes `audio/last-run.json` (counts + sample errors) and commits it even on failure.
- `make_audio_pack.py` args starting with `-` must use `=`: `--rate=-5%` (else argparse exit 2).
- edge-tts can hang without a timeout; script uses 45 s per clip, early stop if 40 clips fail, `--max-minutes 50`. Occasional `NoAudioReceived` → just rerun the job (only missing clips are made).
- pdfmake's Roboto lacks `→` and `☐`: `fixGlyphs()` swaps `→`→`»`; draw checkboxes as tiny tables. Never JSON-clone a doc definition (it drops layout functions).
- `App.handoutDoc(o)` fills defaults; tests must pass a preset's `o`.
- Starting a server with `&` then `pkill` makes the Bash call exit 144; use `run_in_background`. A background server is stopped after ~30 min of a reply ending; restart it before the next smoke run.
- Background watchers die at their time limit; poll `gh run view <id> --json status,conclusion`.
- pdfmake mutates the nodes it lays out: never reuse one node object in several places (`Array(n).fill(node)` drew the dialogue worksheet's ruled lines in the wrong place in 3.4.0). Build a fresh object each time (`Array.from({length:n}, makeNode)`).
- A phrase section's indexes are IDs; append only.
- The Filipino neural voice mangles acronyms and English abbreviations (PRN, BP, Doc → "docee", sentence-initial "I-inform" → "ay-inform"). Give such listening lines a respelled 4th item; data_check enforces it for LISTENING only.
- The Filipino voice reads an all-caps word as letters (good for acronyms) only because `pronounce.js` spells it; anything that bypasses `App.spoken` (a new speak path) would lose that. Route every playback through `App.speak`/`App.speakAsync`.
- `tools/collect-texts.js`: never give `add` an optional 2nd parameter; lists call it as `forEach(add)`, which passes the index (3.6.2 nearly recorded paragraphs 2+ un-respelled). Use the separate `addRaw`.
- Playwright `pg.evaluate("... App.x = (a) => {...}")`: when the expression's value is a function, Playwright calls it. End stubbing expressions with `; 0`.
- New discharge questions go in the `MORE` list at the end of `psych-discharge.js` (appended to the section and to the end of the field's `ask`), never into `FIELDS[].ask`.
- New picks are plain strings, so appending them is safe; smoke tests click picks by index, so append rather than insert.
- The version appears in `data/app-meta.js`, the top `data/changelog.js` entry and `sw.js`; grep for the old string before a bump.
- Discharge practice answers are keyed by question index within a discharge field's `ask`. Changing `psych-discharge.js` asks would both break phrase IDs and misalign case answers: append only.
- `.eyebrow` is uppercased by CSS, so Playwright `inner_text` returns capitals; compare lowercased.
- `js/views.js` creates `App.views`; later view files must not reassign it (use `App.views || {}` so data_check can load them in Node).
- In `app.js`, `routes` is built before `V.more`/`V.practice` exist; register views defined in app.js with `routes.push` after their definition, or the route stores `undefined` and the page shows "fn is not a function".
- In `affixes.js`, build-drill distractors are generated from the seg and filtered against every real word in `AFFIX_ITEMS`, so a wrong option is never another listed word; a written hyphen is attached to the prefix piece by `pieces()`.
- Tile icons inside `.tile h3` need the `.tile h3 svg` size rule; without it an inline SVG fills the tile.
- A view must have exactly one `h1` at the top for `App.decorate` to place the breadcrumb and pin correctly; views that draw their own `.breadcrumb` are left alone.
- Element screenshots on phone show the sticky header over the card; that's an artifact, not a layout bug.
- Medication/diagnosis "picks" in discharge mirror the form's examples (olanzapine, fluphenazine decanoate); keep them generic with blanks.
- Root drill explanations must not gloss the root from the dictionary: roots are often homographs (`basahin` showed "basa (wet)"). Explain with the word's own meaning.
- Typed drills: compare against the raw line AND `App.spoken(line)`, because the spoken form respells (`y medya` → `i medya`) and a learner may type either. Test items by typing the model answer lowercased with `. , ?` removed.
- The dictation drill autoplays 150 ms after drawing; smoke stubs `App.speak` and reads the last spoken line to know which item is on screen. Wait at least 240 ms after Start / Next / Try again before reading it.
- Find the mistake: an item must be wrong for every careful speaker, not merely informal. Left out on purpose because they are heard in real speech: `pumunta ng ospital`, `gusto ko kumain` (no linker), `Bakit itinigil mo…`, loose placement of po, `nagkain`, `kakagising`. A focus mismatch has two possible fixes, so make the rest of the sentence force one (`Kumain ko ng mangga`: the ng shows the verb is right and ko is wrong).
- Focus drill: when both nouns are people, the "new verb + old markers" wrong option is a real sentence with the roles swapped (`Tinawag ang doktor ng nars`); say so in `why`.
- The typed focus set must use `exact`: with `App.similarity` ≥ 80 a five-word sentence with the wrong verb still passes.
